## Test Scenarios

### Q01: Valid plan preview and import
- **Preconditions**: A valid JSON plan matching `my-tracker-ai-plan.schema.json`.
- **Steps**: Select the file via the import UI. Confirm the preview.
- **Expected**: All Goals, Phases, Tasks, and Checklist items are written atomically. A success summary is displayed. Data appears correctly in the UI.
- **Evidence**: Automated parsing/import unit tests.

### Q02: Invalid schema rejection
- **Preconditions**: A JSON file with missing required fields (e.g. missing `goals`).
- **Steps**: Select the file for import.
- **Expected**: Import is rejected immediately with a user-friendly error path. No partial data is written.
- **Evidence**: Automated validation tests.

### Q03: Semantic error rejection
- **Preconditions**: A JSON file with duplicate IDs or broken phase/goal references.
- **Steps**: Select the file for import.
- **Expected**: Semantic validation fails. Error summary is shown. No data is written.
- **Evidence**: Automated validation tests.

### Q04: Transactional rollback on failure
- **Preconditions**: Force an IndexedDB transaction failure during the import write phase.
- **Steps**: Attempt to import a large plan.
- **Expected**: The transaction is caught, rolled back. No partial data exists in the database.
- **Evidence**: Automated transaction rollback tests.

### Q05: Real AI Tool Plan (Manual Required)
- **Preconditions**: A plan generated by a real AI tool (e.g., using Gemini) following the provided prompt.
- **Steps**: Save the AI output as `.json` and import it into a fresh workspace.
- **Expected**: The generated plan imports correctly with hierarchy/order intact.
- **Evidence**: Manual verification required.
